# 3인 편집실 (edit-writing-room)

## 적용 후 남는 결과

1. 지금 상태 — 중심 판단 한 문장 + 안정적인 지점
2. 독자가 막히는 곳 (3개 이내) + 구조 진단
3. 우선 수정 세 가지 — 현재 문장 → 수정 방향 문장 → 이유
4. 반드시 보존할 부분 + 구체화 필요 목록
5. 총평 — 전면 수정 필요 여부 판정

최종 원고는 사용자가 `반영해줘`라고 했을 때만 낸다.

## 이 문서의 자리표시자

| 표기 | 뜻 |
|---|---|
| `{BASE}` | `hong-voice-reference` 스킬이 반환하는 Base directory |
| `{SKILL_DIR}` | 이 스킬이 설치된 디렉터리 |
| `{적재 폴더}` | 교정 카드와 거절 패턴을 누적할 폴더. 쓰는 사람이 정한다 |

`hong-voice-reference`는 홍작가 개인 문체 정본이라 이 저장소에 포함되지 않는다. 없으면 이 스킬은 **폴백 모드**로 돌고, 아래 `편집 기준 최소 카드`만으로 편집자 단계를 끝낸다. 중단하지 않는다.

자기 문체 정본을 쓰려면 `{BASE}` 자리에 그 스킬의 경로를 넣고, 1층 시선·2층 단어·3층 흔적·4층 승인 원문에 해당하는 파일을 조달표대로 넘기면 된다.

## 3인의 정의

이름의 3인은 작가·독자·편집자다. 글 한 편에는 원래 이 세 자리가 필요한데, AI에게 맡기면 한 에이전트가 세 자리를 혼자 차지한다. 쓰고, 스스로 읽고, 스스로 잘 썼다고 판단한다. 이 스킬은 그 자리를 다시 갈라놓는다.

| 자리 | 누가 맡는가 | 결정하는 것 |
|---|---|---|
| 작가 | 사람(사용자) | 무엇을 쓸지, 경험을 어디까지 공개할지, 판단 강도, 발행 여부 |
| 독자 | 서브에이전트 | 어디서 막혔는지 (수정 권한 없음) |
| 편집자 | 서브에이전트 | 어떻게 고칠지 (사실·경험 추가 권한 없음) |

메인 에이전트는 네 번째 인원이 아니라 진행 담당이다. 원본을 잠그고, 두 역할을 순서대로 부르고, 결과를 점검해 작가에게 넘긴다. 작가의 자리를 대신하지 않는다. 원고의 관점, 경험 공개, 강한 판단, 게시 여부는 사용자가 결정한다.

## 핵심 개념

```text
작가(사용자)      원고·범위·승인
메인 에이전트     원본 잠금·조정·최종 점검
  → 독자 서브에이전트    반응과 막힘만 보고 (수정 금지)
  → 편집자 서브에이전트  독자 리포트를 반영해 수정 (hong-voice-reference 3층 적용)
  → 메인 에이전트        저자성·범위·사실 점검 후 작가에게 인계
```

독자와 편집자는 부모 대화를 모르는 새 문맥의 서브에이전트다. 역할 정의와 폴백 기준은 `references/` 세 파일에 있고, 문체 정본은 `hong-voice-reference` 스킬에 있다. 서브에이전트는 `Skill` 도구를 쓰지 못하므로 메인이 정본을 호출해 **절대 경로**를 확보하고, 역할 브리프와 문체 3층을 모두 절대 경로로 넘긴다. 폴백일 때만 최소 카드 본문을 프롬프트에 직접 넣는다.

## 호출 축 세 가지

이 스킬에는 다이얼이 세 개 있다. 셋은 서로 다른 것을 정하므로 하나의 `모드`로 묶어 부르지 않는다.

| 축 | 값 | 기본값 | 정하는 것 |
|---|---|---|---|
| 역할 | 독자 · 편집자 · 편집실 · 병렬 | 편집실 | 누가 원고를 보는가 |
| 출력 | 제안 · 선택반영 · 전체반영 | 제안 | 무엇이 돌아오는가 |
| 강도 | 최소 · 표준 · 구조 | 표준 | 어디까지 손대는가 |

축 사이에는 다음 구속이 걸린다.

- `역할 = 독자`이면 출력은 `제안`으로 고정한다. 독자는 수정 권한이 없으므로 다른 값을 묻지도 받지도 않는다. 강도 축도 적용되지 않는다.
- `출력 = 전체반영`은 사용자가 원고 전문을 요구했을 때만 연다. 추정으로 이 값에 들어가지 않는다.
- `출력 = 선택반영`은 제안을 낸 뒤 사용자가 번호를 고른 다음에만 들어간다 (STEP 5).
- `강도 = 구조`는 사용자가 명시했을 때만 연다.

`기준 축`(정본·폴백)은 사용자가 고르는 값이 아니라 STEP 0의 호출 결과로 정해진다. 위 세 축과 섞어 부르지 않는다.

## When to Use

- `3인 편집실로 봐줘`, `독자와 편집자에게 검토시켜줘`, `멀티 에이전트로 퇴고해줘`
- `40~50대 AI 입문 독자가 어떻게 읽을지 봐줘`
- `내 개인적인 생각은 살리고 편집해줘`
- 초안·칼럼·페이스북 글·블로그 글·브런치 글·에세이·책 한 챕터를 독자 검토 후 편집할 때

다음에는 전체 흐름을 쓰지 않는다.

| 상황 | 사용할 스킬 |
|---|---|
| 맞춤법·오탈자 한두 곳, 지정 구간 부분 수정 | `edit-quick` |
| 문체 변환만 (독자 검토 불필요) | `edit-hongstyle` |
| AI 흔적·금지어만 제거 | `edit-deai` |
| 책 전체 독자 검증 (페르소나 3~5명) | `book-feedback-reader` |
| 장편 원고 3패스 퇴고 | `book-editing` |
| 원고 없이 아이디어만 탐색 | 해당 없음 (일반 대화) |

이 스킬은 짧은 원고 또는 장편의 한 작업 단위에 쓴다.

## 중단 금지 규칙

이 스킬은 **어떤 경우에도 파일이 없다는 이유로 멈추지 않는다.** 최소 카드가 스킬 안에 들어 있고, `hong-voice-reference` 정본은 호출되면 쓰는 상위 기준이다.

산출물에 다음 문구를 쓰지 않는다.

```text
정본 파일을 첨부해주시면 이어서 진행하겠습니다
파일을 읽어야 시작 가능합니다
진행하시려면 다음 중 하나를 선택해주세요
정본 없이 진행하므로 edit-quick으로 전환합니다
```

파일 첨부 요구, 선택지 제시, 다른 스킬로의 전환 권유, 단계 보류는 모두 금지한다. 기준 파일이 없으면 아래 최소 기준으로 그대로 편집한다.

## 실행 흐름

```text
STEP 0 기준 확보·기준 모드 결정
STEP 1 요청 확인·원본 잠금

STEP 5 사용자 피드백 반영
```

# STEP 0. 기준 확보 (1회)

**메인 에이전트가 직접 수행한다.** 서브에이전트는 `Skill` 도구를 쓰지 못하므로 정본 스킬을 스스로 호출할 수 없다. 다만 절대 경로를 받으면 파일은 직접 읽는다. 메인이 할 일은 **경로를 확보해 넘기는 것**이지 본문을 통째로 프롬프트에 붙이는 것이 아니다.

```text
1) 대화 첨부      기준 문서가 첨부돼 있으면 그것을 쓴다
2) 정본 스킬      Skill 도구로 `hong-voice-reference`를 호출한다
                  → 반환된 Base directory를 BASE로 기록한다
                  → 메인은 판정 근거로 01-voice.md만 읽어 둔다 (기준 모드 종합 시 필요)
3) 건강 점검      {BASE}/scripts/validate.py를 1회 실행한다 (아래)
4) 실패           즉시 폴백 모드로 진행. 재시도·요청·보고 없음
```

### 정본 건강 점검 (호출마다 1회)

정본의 갱신 절차는 5단계인데 그중 3·5단계(파일 머리 날짜, SKILL.md version·변경 이력)를 사람이 빠뜨려도 아무도 모른다. 실제로 2026-09-15에 3층만 고치고 나머지를 빠뜨린 이력이 있고 일주일간 발견되지 않았다. 정본은 `validate.py`를 갖고 있지만 "갱신 후 반드시 1회 실행"을 강제할 장치가 없다.

**점검을 호출 경로에 올린다.** 편집실이 열릴 때마다 한 번 돌면 드리프트가 그날 드러난다.

```bash
python3 {BASE}/scripts/validate.py
```

| 결과 | 처리 |
|---|---|
| `ok: true` | 그대로 진행한다. 산출물에 따로 적지 않는다 |
| `ok: false` | **작업은 계속한다.** 산출물 말미 실행 모드 줄 뒤에 `정본 점검: <errors 첫 줄>`을 한 줄로 덧붙인다 |
| 실행 불가 (스크립트 없음·파이썬 없음) | 아무것도 적지 않고 진행한다 |

점검 실패를 이유로 멈추거나, 사용자에게 고치라고 요구하거나, 폴백으로 내려가지 않는다. 정본 파일은 이 스킬이 고치지 않는다. **보고만 한다.**

사본이 여러 개라 어느 것이 실행되는지 확인이 필요하면 별도의 사본 드리프트 감시 도구를 쓴다. 이 스킬의 실행 경로에는 넣지 않는다 — 편집 작업마다 돌릴 점검이 아니다.

### 서브에이전트에 넘기는 것

정본 모드에서는 **절대 경로 목록**을 넘긴다. 본문을 프롬프트에 복사하지 않는다.

```text
{BASE}/references/01-voice.md        1층 시선·어조·논리·리듬·마무리      7,061자
{BASE}/references/02-glossary.md     2층 단어·문장 선택                 11,275자
{BASE}/references/03-anti-traces.md  3층 AI 흔적·금지어·계량            10,379자
{BASE}/references/04-examples.md     4층 승인 원문 (저자성 판정 근거)     5,673자
```

**네 개를 늘 다 넘기지 않는다.** 서브에이전트는 새 문맥이라 정본의 `같은 대화에서 이미 읽은 파일은 다시 읽지 않는다`가 발동하지 않는다. 넘긴 경로는 호출마다 처음부터 읽힌다. 아래 조달 범위에서 그 호출에 필요한 층만 고른다.

경로는 반드시 절대 경로로 변환해 넘긴다. 상대 경로는 서브에이전트의 작업 디렉터리 기준으로 해석되어 실패한다. 역할 브리프(`references/reader-brief.md`·`references/editor-brief.md`)도 같은 방식으로 절대 경로로 넘긴다.

폴백 모드에서는 읽을 파일이 없으므로 **최소 카드 전문**을 프롬프트에 직접 넣는다.

### 역할별 조달 범위

STEP 1에서 역할이 확정되기 전이라도 호출 자체는 가볍다. 실제 3층 읽기는 편집자 단계가 있을 때만 필요하다.

| 역할·단계 | 강도 | 넘기는 경로 | 분량 |
|---|---|---|---|
| 독자 | — | 없음 (BASE만 확보. 독자는 편집하지 않는다) | 0자 |
| 편집자 · 편집실 · 병렬 | 최소 | 01 · 03 | 17,440자 |
| 편집자 · 편집실 · 병렬 | 표준 (기본) | 01 · 02 · 03 | 28,715자 |
| 편집자 · 편집실 · 병렬 | 구조 | 01 · 02 · 03 · 04 | 34,388자 |
| 선택 반영 재호출 (STEP 5) | — | 없음. 문체 판정은 STEP 3에서 끝났다 | 0자 |

**05-corrections는 경로로 넘기지 않고 메인이 읽어 발췌한다.** 정본 규격은 `같은 표현을 두 번 이상 고쳤을 때만`이고, 파일이 3,405자로 작다. 메인이 STEP 0에서 읽어 두고 원고와 겹치는 항목만 편집자 프롬프트에 본문으로 넣는다. 겹치는 항목이 없으면 아무것도 넣지 않는다.

이 발췌는 우선순위 사다리에서 **규칙 3층보다 위**다. 01·02·03의 규칙과 충돌하면 교정 이력이 이긴다. 편집자에게 넘길 때 그 순위를 함께 적는다.

```text
[교정 이력 — 규칙 3층보다 우선]
(수정 전) → (수정 후) | (이유) | (채널)
```

`{적재 폴더}/교정 카드 적재.md`도 같은 방식으로 본다. 아직 정본에 승격되지 않았으므로 **참고로만** 넘기고, 승격된 05 항목과 구분해 표기한다.

**2층을 최소 강도에서 빼는 이유** — 최소 강도는 범주 1·3과 상투 표현 사전만 보고 L3 일부만 고친다. 단어 선택 단계에 들어가지 않으므로 2층이 판단에 쓰이지 않는다.

**4층을 조건부로 두는 이유** — 정본의 호출 규격(`00-caller-blocks.md`)이 04-examples를 `문체 판정이 갈릴 때만`으로 정한다. 구조 강도는 문단을 재배열하므로 저자성 판정이 갈릴 확률이 높아 미리 넘긴다. 최소·표준에서는 넘기지 않고, 편집자가 판정이 갈리는 자리를 만나면 고치지 말고 `판정 보류: (위치) — 승인 원문 대조 필요`로 남긴다. 메인이 STEP 4에서 04-examples를 직접 읽어 그 자리만 판정한다.

판정 보류가 한 원고에서 3건을 넘으면 다음 호출부터 04 경로를 함께 넘긴다. 왕복이 조달보다 비싸지는 지점이다.

### 실행 모드 표기 (필수)

산출물 말미에 아래 한 줄을 **항상** 붙인다. 성공·실패 모두 적는다.

```text
문체 기준: hong-voice-reference (1층·2층·3층 적용)
문체 기준: 폴백 최소 카드 (hong-voice-reference 호출 실패)
```

호출은 성공했으나 일부 파일을 열지 못했으면 확보한 층만 경로로 넘기고, 나머지는 최소 카드의 해당 줄을 함께 넣는다. 이때 표기는 `문체 기준: hong-voice-reference (1층·3층) + 최소 카드 보완`처럼 실제 상태를 쓴다.

### 우선순위 사다리

정본 SKILL.md의 사다리를 그대로 따른다. 맨 아래 한 단(최소 카드)만 이 스킬이 덧붙인다.

```text
사실·원문
→ 현재 사용자 지시
→ 승인된 경험·사용자 표현
→ 04-examples · 05-corrections     ← 규칙 3층보다 위
→ 프로젝트별 기준 (책·연재·기관 사전)
→ 채널 기준
→ 01-voice
→ 02-glossary
→ 03-anti-traces
→ 최소 카드 (폴백 모드에서만)
```

`04-examples`와 `05-corrections`가 규칙 3층보다 **위**라는 점을 편집자에게 그대로 전달한다. 정본의 절대 규칙이 "기준이 규칙과 승인 원문 사이에서 갈리면 `04-examples.md`의 실제 문단을 따른다"이므로, 규칙에 맞추려고 승인 원문을 깎으면 위반이다.

# STEP 1. 요청 확인과 원본 잠금

받을 것 다섯 가지. 대화나 파일에서 이미 확인되면 다시 묻지 않는다. 없으면 한 번에 하나씩 묻는다.

| 항목 | 값 | 기본값 |
|---|---|---|
| 원고 | 본문 또는 절대 경로 | 필수 |
| 채널 | 범용·페이스북·블로그·브런치·책 | 원고에서 추정 후 확인 |
| 역할 | 독자 / 편집자 / 편집실 / 병렬 | 편집실 |
| 출력 | 제안 / 선택반영 / 전체반영 | 제안 |
| 강도 | 최소 / 표준 / 구조 | 표준 |

### 축 확정 선언 (필수)

호출문 한 줄에서 세 축을 모두 읽어낼 수는 없다. 추정한 값을 **작업 시작 전에 한 줄로 먼저 밝힌다.** 이 줄에서 사용자 의도와의 어긋남이 드러난다.

```text
역할: 편집자 · 출력: 제안 · 강도: 최소 · 채널: 블로그
```

호출문에 수정을 뜻하는 말(`고쳐줘`, `편집해줘`, `다듬어줘`)이 있어도 출력 축은 `제안`이 기본이다. 수정을 뜻하는 말과 원고 전문을 요구하는 말(`반영해줘`, `수정본 줘`, `전체 고쳐줘`)은 다르다. 앞엣것은 역할 축의 신호이고 뒤엣것만 출력 축을 `전체반영`으로 옮긴다.

선언 줄과 다른 값을 사용자가 원하면 그 자리에서 고쳐 받고 다시 시작한다. 작업 도중에 축을 바꾸지 않는다.

원본은 최신 사용자 제공본 또는 최신 승인본 하나로 잠근다. 이전 보조 초안에서 다시 시작하지 않는다. 두 서브에이전트에는 같은 원본을 전달한다.

# STEP 2. 독자 서브에이전트 호출

Agent 도구로 호출한다. `subagent_type`은 `general-purpose`를 쓴다.

프롬프트에 넣을 항목:

- `references/reader-brief.md`를 읽으라는 지시 (경로는 스킬 디렉터리 기준 절대 경로로 변환해 전달)
- 원고 전문 또는 절대 경로
- 채널과 글의 목적
- 반환 형식: 독자 리포트만

완료 기준: 모든 High·Mid 지적이 원고 위치와 연결되고, 수정문 없이 리포트만 돌아온다.

# STEP 3. 편집자 서브에이전트 호출

독자 리포트가 돌아온 뒤 순차 호출한다.

프롬프트에 넣을 항목:

- `references/editor-brief.md`를 읽으라는 지시
- **편집 기준** — 정본 모드는 STEP 0의 조달 범위에서 **강도에 해당하는 절대 경로만** 넘기고 순서대로 읽으라고 지시한다. 폴백 모드는 최소 카드 **전문**을 프롬프트에 직접 넣는다
- 정본 모드일 때: 받은 경로를 층 순서대로 적용하라는 지시. `Skill` 도구는 쓰지 말고 받은 경로만 읽으라고 명시한다
- 넘기지 않은 층은 **없는 것으로 치고 진행**하라는 지시. 경로를 찾아 나서거나 부족하다고 보고하지 말 것. 4층을 받지 않았는데 저자성 판정이 갈리면 `판정 보류: (위치)`로 남길 것
- AI 흔적 지수는 `03-anti-traces.md` §11 정의(범주 1~8 + §10 사전)로만 산출하라는 지시
- **교정 이력 발췌** — 위 형식으로. 원고와 겹치는 항목이 없으면 이 항목을 넣지 않는다
- **후보 추출 도구 경로** — `{이 스킬 디렉터리}/scripts/scan-traces.py`의 절대 경로와 실행법을 넘긴다. §10 사전 대조를 손으로 하지 말고 이 도구를 먼저 돌린 뒤, 나온 후보에만 §5-1 판정을 적용하라고 지시한다

```bash
python3 {SKILL_DIR}/scripts/scan-traces.py --canon {BASE}/references/03-anti-traces.md --manuscript {원고 경로} --json
```

도구 결과는 **바닥값이지 전부가 아니다.** 형태 변이(`~라고` ↔ `~다고`)와 범주 1~8의 구조적 흔적(§5-3·§6·§7)은 도구가 못 잡으므로 편집자가 직접 읽는다. 도구를 못 돌리는 환경이면 기존대로 손으로 대조하고, 그 사실을 보고하지 않고 그냥 진행한다.
- 편집 강도와 채널
- 원고 전문 또는 절대 경로
- 독자 리포트 전문 (`역할 = 편집자`·`역할 = 병렬`에서는 이 항목이 없다. 없으면 0층을 건너뛰고 원고만 독립 편집하라고 명시한다)
- 변경 금지 영역과 사용자 승인 문구
- 출력 축 (제안 / 전체반영)
- 완료 조건: 출력이 `제안`이면 수정 제안 3~5건을 `선행 → 현재 문장 → 수정 방향 문장 → 이유`로, `전체반영`이면 수정 원고 전문을 반환할 것. 자료 부족을 이유로 반환을 보류하지 말 것

서브에이전트가 파일을 못 읽었다고 보고하며 빈손으로 돌아오면 그 응답을 사용자에게 전달하지 않는다. 메인이 기준 본문을 넣어 즉시 재호출한다.

완료 기준: 독자 리포트의 High 항목을 반영하거나 보류 이유를 밝히고, 원고에 없는 경험·사실을 추가하지 않는다. 출력이 `제안`이면 원고 전문을 다시 쓰지 않는다. 고칠 문장만 인용하고 그 자리에 들어갈 완성 문장을 제시한다.

## 역할 = 병렬

사용자가 `병렬로`, `한 번에 독자와 편집자`, `빠르게`라고 명시하면 Agent 두 개를 한 메시지에서 동시에 호출한다. 이때 편집자는 독자 리포트를 받지 못하므로 원고만 독립 편집하고, 메인 에이전트가 두 결과를 대조해 반영한다. 기본값은 순차 호출이다.

# STEP 4. 메인 종합

편집자 결과를 그대로 전달하지 않는다. 0번을 먼저 해소한 뒤 다섯 항목을 점검한다.

0. 편집자가 남긴 `판정 보류` 항목이 있는가. 있으면 메인이 `{BASE}/references/04-examples.md`를 직접 읽어 그 자리만 판정한다. 승인 원문에 있는 표현이면 원문을 유지하고, 아니면 3층 기준으로 처리한다. 보류를 그대로 사용자에게 넘기지 않는다.
1. 독자 지적과 수정 원고가 연결되는가.
2. 홍작가의 개인적 판단이 일반론으로 약해지지 않았는가.
3. 원문에 없는 경험·수치·인용·제품 사실이 생기지 않았는가.
4. 최신 사용자 승인 문구와 수정 범위가 보존됐는가.
5. 원고 본문과 내부 편집 보고서가 분리됐는가.

이어서 하네스 점검을 실행한다. 편집자가 자기 결과를 스스로 합격 처리하지 않도록, 이 점검은 메인이 다시 한다.

| 점검 | 합격 기준 |
|---|---|
| 금지어·상투어 | 0건 |
| 추상 형용사·모호 부사 | 0건 |
| AI 흔적 지수 | 수정 전 대비 하락, 등급 `낮음` 권장 |
| 사실 보존 | 수치·고유명사·인용·날짜 불일치 0건 |
| 분량 | 원문의 120% 이내 |
| 일반론 | 편집자가 사례를 지어 채우지 않고 `구체화 필요`로 남겼는가 |

메인이 지수를 다시 셀 때도 같은 도구를 쓴다. 편집자와 메인이 서로 다른 방식으로 세면 전/후 비교가 어긋난다.

미달 항목이 있으면 해당 항목만 수정 후 재점검, 최대 2회. 2회 후에도 남으면 위치와 사유를 보고한다.

## 출력 형식 — 제안 (기본값)

원고 전체를 고쳐서 내지 않는다. 어디를 어떻게 고칠지 짚어주고, 고칠지 말지는 작가가 정한다.

```markdown
## 지금 상태
[안정적인 지점 1~2줄. 이 글의 중심 판단 한 문장]

## 독자가 막히는 곳
[3개 이내. 각 항목은 위치 + 무엇이 안 보이는지]

## 구조 진단
[전체 흐름을 텍스트 다이어그램으로 그리고, 축이 엉키거나 연결이 빠진 지점만 지적]

## 우선 수정 세 가지

### 1. [수정 항목 이름]

선행: 없음 (또는 N번)

현재
> [원고 문장 그대로 인용]

수정 방향
> [고친 문장. 완성된 대체 문장으로 제시]

[왜 이렇게 바꾸는지 1~2줄]

### 2. …
### 3. …

## 반드시 보존할 부분
[원문 문장을 그대로 인용. 6개 이내]

## 구체화 필요
[작가가 경험·사례·수치로 채울 자리. 대신 쓰지 않는다]

## 총평
[전면 수정할 원고인지 아닌지 한 문단으로 판정. 무엇을 더하고 무엇을 덜어낼지]

## 점검 결과
[실행 모드(정본/폴백) + AI 흔적 지수 전→후 1줄]
```

제안 개수는 3개를 기본으로 하고 최대 5개를 넘지 않는다. 전면 수정이 필요한 원고라도 한 번에 다 내지 않고, 우선 세 개를 내고 반영 여부를 받은 뒤 다음 묶음으로 넘어간다.

각 제안의 `수정 방향`은 방향 설명이 아니라 **바로 붙여넣을 수 있는 완성 문장**으로 쓴다. `~를 구체화하면 좋겠습니다` 같은 지시형은 제안이 아니다.

## 출력 형식 — 반영 (선택반영·전체반영 공용)

출력 축이 `선택반영` 또는 `전체반영`일 때 쓴다. 전체반영은 사용자가 `반영해줘`·`수정본 줘`·`전체 고쳐줘`라고 했을 때만 열린다. 선택반영은 STEP 5에서 제안 번호를 받은 뒤에 들어간다.

```markdown
## 이 글의 중심 판단
[한 문장]

## 반영한 것
[3~5개. 수정 전 → 수정 후로 짝지어]

## 반영하지 않은 것과 이유
[전체반영은 있을 때만. 선택반영은 고르지 않은 제안 번호·이름·사유를 필수로 적는다]

## 최종 원고
[완성된 원고]

## 구체화 필요
[작가가 채울 자리]

## 점검 결과
[축 선언 + 실행 모드 + 반영 주체 + AI 흔적 지수 전→후 + 하네스 통과 여부 1줄]
```

`역할 = 독자`일 때도 리포트 원본을 그대로 내보내지 않는다. 메인이 `지금 상태`와 `독자가 막히는 곳`으로 압축하고, `[원고근거]`·`[독자추정]` 라벨이 붙은 상세 항목은 그 아래에 둔다.

# STEP 5. 사용자 피드백 반영

제안을 낸 뒤 사용자가 번호를 고르면 출력 축이 `선택반영`으로 넘어간다. 이 단계에서 피드백이 새지 않도록 실행 주체와 순서를 아래로 고정한다.

## 반영은 편집자 서브에이전트가 한다

메인 에이전트가 원고 문장을 직접 고쳐 넣지 않는다. 메인은 진행 담당이지 네 번째 인원이 아니다. 선택된 제안을 들고 편집자를 다시 호출한다.

재호출 프롬프트에 넣을 항목:

- `references/editor-brief.md` 절대 경로와 그 문서의 `선택 반영 재호출` 절을 적용하라는 지시
- STEP 1에서 잠근 원본 전문 또는 절대 경로
- 선택된 제안 전문 — 현재 문장·수정 방향 문장·이유를 그대로 넣는다. 요약하지 않는다
- 선택되지 않은 제안의 번호와 이름. **반영 금지 목록**으로 명시한다
- 최신 사용자 승인 문구와 변경 금지 영역
- 채널과 강도
- 완료 조건: 선택된 제안만 원고에 넣고, 그 밖의 구간은 원본 문장을 글자 그대로 둘 것

**문체 정본 4층 경로는 넘기지 않는다.** 선택 반영은 새 편집이 아니라 이미 합의된 문장을 원고에 넣는 작업이다. 문체 판정은 제안을 만든 STEP 3에서 끝났고, `수정 방향` 문장은 그때 1~4층을 적용해 쓴 완성 문장이다. 여기서 34,000자를 다시 읽히면 같은 판정을 반복하는 시간만 들고, 합의된 문장을 편집자가 다시 손볼 여지가 생긴다.

예외는 하나다. 사용자가 제안을 고르면서 `수정 방향` 문장을 직접 고쳤고 그 수정이 문체 판정을 요구하면, 그 구간에 한해 `03-anti-traces.md` 경로 하나만 넘긴다. 1·2·4층은 그때도 넘기지 않는다.

서브에이전트 호출이 불가능한 환경이면 메인이 반영하되, 산출물 말미에 `반영 주체: 메인 (서브에이전트 호출 불가)`를 적는다. 조용히 대신하지 않는다.

## 제안 간 의존 확인

제안은 서로 독립이 아니다. 앞 제안이 도입부 구조를 바꾸면 뒤 제안이 그 도입부를 전제로 쓰였을 수 있다.

- 제안을 낼 때 각 항목에 `선행: 없음` 또는 `선행: N번`을 적는다 (STEP 4 출력 형식)
- 사용자가 선행이 걸린 제안만 고르면 반영 전에 짝을 알린다 — `3번은 1번을 전제로 합니다. 1번 없이 3번만 넣으면 (위치)의 연결이 끊깁니다.`
- 알린 뒤에도 사용자가 3번만 원하면 그대로 반영하고, 끊긴 자리를 `구체화 필요`에 남긴다. 임의로 메워 넣지 않는다

## 승인본 고정

반영이 끝나면 그 결과가 새 원본이다. 승인본을 대화에만 두지 않는다.

- 원고가 프로젝트 폴더의 파일이면 같은 폴더에 `00 승인본.md`로 저장하고 `last_updated`를 적는다
- 원고를 대화 본문으로 받았으면 저장 여부를 한 번 묻는다. 사용자가 거절하면 저장하지 않고 넘어간다
- 다음 호출의 STEP 1은 이 승인본을 원본으로 잠근다. 이전 제안본이나 보조 초안에서 다시 시작하지 않는다

## 선택 구간 재점검

STEP 4의 하네스 점검은 편집자 결과에 대해 돌았다. 부분 반영은 새 문장과 원본 문장이 섞이므로 한 번 더 본다. 대상은 **바뀐 구간과 그 앞뒤 문단까지**이며, 원고 전체를 다시 세지 않는다.

| 점검 | 합격 기준 |
|---|---|
| 금지어·상투어 | 바뀐 구간 0건 |
| 사실 보존 | 바뀐 구간의 수치·고유명사·인용·날짜 불일치 0건 |
| 리듬 | 삽입 문장과 원본 문장 사이에 같은 길이·역할 3연속이 생기지 않았는가 |
| 분량 | 원문의 120% 이내 |

AI 흔적 지수는 구간 재점검에서 다시 산출하지 않는다. 척도가 원고 전체 1,000자 환산이므로 구간만으로는 전/후 비교가 성립하지 않는다.

## 거절 기록

- `1번과 3번만 반영해줘` 같은 선택을 받는다. 고르지 않은 제안은 같은 원고에서 다시 꺼내지 않는다
- 사용자가 거절 사유를 말하면 그 문장을 그대로 남긴다. 사유가 없으면 `사유 없음`으로 적고 추측해 채우지 않는다
- 거절 기록은 **그 자리에서 볼트 파일에 남긴다.** 대화창 출력만으로 끝내지 않는다

```text
{적재 폴더}/교정 카드 적재.md  →  ## 거절 패턴 표에 한 줄 추가
```

- 같은 제안이 이미 있으면 새 줄을 만들지 않고 `횟수`를 올리고 `최근`을 갱신한다
- `횟수` 3 도달 시 `05-corrections.md` 승격 후보로 표시한다. 승격 자체는 사용자 승인 뒤 별도 세션에서 한다
- 적재 파일이 없으면 만들지 않고 대화창 출력으로 끝낸다. 경로를 새로 지어내지 않는다
- 한 번의 선호나 한 번의 거절을 곧바로 공용 규칙으로 만들지 않는다

## 교정 카드 적재

사용자가 결과물의 표현을 직접 고치면 정본의 규정대로 교정 카드를 만든다.

```text
[교정] 수정 전 → 수정 후 | 이유 | 채널
```

정본은 "실행 중 파일을 고치지 않고 작업 말미에 카드만 출력한다"고 정한다. 그 규정은 **정본 스킬 파일**에 대한 것이다. 세션이 끝나면 초기화되기 때문이다. 볼트 파일은 초기화되지 않으므로 카드를 볼트에 남기는 것은 그 규정에 걸리지 않는다.

- 카드를 대화창에 출력하고, **같은 줄을 `{적재 폴더}/교정 카드 적재.md`의 `## 교정 카드` 표에 추가한다**
- 같은 `수정 전 → 수정 후` 조합이 있으면 `횟수`를 올리고 `최근`을 갱신한다
- `횟수` 3 도달 시 `승격 후보`에 `O`를 적는다. `05-corrections.md`로의 승격은 사용자 승인 뒤 별도 세션에서 한다
- 정본의 `references/05-corrections.md`를 이 스킬이 직접 고치지 않는다. 고쳐도 남지 않고, 사본 드리프트만 늘어난다

출력만 하고 사라지던 카드가 여기서 멈춘다. 2026-09-22 기준 정본의 교정 이력 표는 12행이고 승격 사례가 없다. 루프가 안 돈 원인은 판단이 아니라 **적재할 자리가 없던 것**이다.

## 이어지는 라운드

- 세 개를 다 반영한 뒤 남은 항목이 있으면 다음 세 개를 제안한다. 이때 원본은 방금 고정한 승인본이다
- 사용자가 문장이나 판단을 직접 고치면 그 수정본이 최신 승인본이 된다
- 여러 원고에서 반복된 절차만 이 스킬에 승격한다

## 호출 예시

```text
이 원고를 3인 편집실로 검토해줘.
→ 역할: 편집실 · 출력: 제안 · 강도: 표준
```

```text
독자 검토만 해줘. 문장은 고치지 마.
```

```text
편집자만 불러서 최소 강도로 봐줘. 내 판단과 문단 순서는 그대로 둬.
→ 역할: 편집자 · 출력: 제안 · 강도: 최소
```

```text
1번과 3번만 반영해줘.
→ 역할: 편집자 · 출력: 선택반영 · 강도: 직전 라운드 값 유지
```

```text
구조 편집까지 허용할게. 40~50대 AI 입문 독자가 따라오도록 제목과 도입부터 다시 봐줘.
```

## 자주 나오는 실패

1. 독자가 편집까지 함 — 독자는 반응과 막힘만 보고한다.
2. 편집자가 저자의 생각을 일반론으로 바꿈 — 판단 강도는 보존하고 근거와 위치만 정리한다.
3. 서브에이전트가 부모 대화를 안다고 가정함 — 역할·원고·채널·승인 문구를 프롬프트에 전부 넣는다.
4. 매번 병렬 호출함 — 독자 반응을 반영해야 하면 순차로 부른다.
5. 정본이 없다고 편집을 멈추고 첨부를 요구함 — 최소 카드로 그대로 진행한다. 이것이 가장 자주 나오는 실패다.
6. 서브에이전트에게 정본 스킬을 호출하게 함 — 서브는 `Skill` 도구를 쓰지 못한다. 메인이 호출해 절대 경로를 넘긴다 — 메인이 STEP 0에서 확보해 기준 본문으로 넘긴다.
7. 독자 시뮬레이션을 실제 조사처럼 보고함 — `[독자추정]`과 `[원고근거]`를 구분한다.
8. 한 번의 교정을 즉시 메모리·사전에 저장함 — 승인과 반복성을 확인한 뒤 승격한다.
9. 최종 원고에 작업 보고서를 섞음 — 보고서와 본문을 분리한다.
10. 일반론을 편집자가 사례로 채움 — 구체 사례·수치가 없는 자리는 `구체화 필요`로 남기고 작가가 채운다.
11. 묻지도 않았는데 원고 전문을 고쳐서 냄 — 출력 축의 기본값은 `제안`이다. 전문은 `반영해줘`를 받은 뒤에 낸다.
12. 수정 방향을 지시문으로 씀 — `구체화하면 좋겠습니다`가 아니라 붙여넣을 완성 문장을 준다.
13. 역할·출력·강도를 한 덩어리 `모드`로 읽음 — 축이 셋이다. STEP 1에서 세 값을 따로 선언한다.
14. `고쳐줘`를 출력 축 신호로 읽음 — 그것은 역할 축 신호다. 출력 축을 옮기는 말은 `반영해줘`·`수정본 줘`·`전체 고쳐줘`뿐이다.
15. 메인이 선택 반영을 직접 손으로 넣음 — 편집자를 재호출한다. 호출이 불가능하면 반영 주체를 산출물에 밝힌다.
16. 선택되지 않은 제안이 슬며시 들어감 — 반영 금지 목록으로 명시해 넘긴다.
17. 승인본을 대화에만 둠 — 다음 라운드의 원본이 풀린다. 파일로 고정하거나 저장 여부를 묻는다.
18. 부분 반영 뒤 점검을 건너뜀 — 바뀐 구간과 앞뒤 문단을 다시 본다.
