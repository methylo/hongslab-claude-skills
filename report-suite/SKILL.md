# report-suite — 보고서 서비스 진입점

보고서 스킬 10종의 안내판이자 분배기다. 이 스킬은 보고서를 직접 쓰지 않는다. **유형을 판별하고 해당 스킬로 넘기는 것**까지가 범위다.

## 보조 파일 안내

| 보조 파일 | 내용 | 참조 시점 |
|----------|------|----------|
| `references/skill-catalog.md` | 10종 명세 카드 (입력·출력·분량·상태) | 유형 안내·판별 시 |
| `references/routing-table.md` | 판별 질문 트리, 경계 사례, 오배정 교정 | 판별이 갈리는 순간 |
| `references/report-standards.md` | 문체·수치·금지어·개인정보 공용 기준 | 개별 스킬 실행 직전 |
| `references/output-formats.md` | .md/.docx/.hwpx 저장 규칙, 파일명 규칙 | 저장 단계 |

**읽기 규칙:** 필요한 시점에만 읽는다. 같은 대화에서 읽은 파일은 다시 읽지 않는다.

## 판별 절차

### 1단계: 입력에서 먼저 읽는다

사용자 요청에 아래 단서가 있으면 질문 없이 배정한다.

| 단서 | 배정 |
|---|---|
| 주간·이번 주·금주·위클리 | `report-weekly` |
| 월간·이번 달·월별·모니터링 | `report-monitoring` |
| 회의·미팅·녹취·전사·액션아이템 | `meeting-minutes` |
| 리서치·조사·분석·트렌드·시장 | `research-report` |
| .hwpx·공고문·모집·한글 양식 | `chungcheong-report` |

### 2단계: 단서가 없으면 3가지만 묻는다

한 번에 묶어서 묻는다. 나눠 묻지 않는다.

> 보고서 유형을 정하기 위해 세 가지만 확인하겠습니다.
>
> 1. **주기** — 정기 보고입니까(일일·주간·월간·연간), 특정 사건에 대한 보고입니까?
> 2. **목적** — 진행 공유입니까, 실적·성과 보고입니까, 근거 제시입니까?
> 3. **제출처** — 내부 공유입니까, 상급 기관·발주처 제출입니까?

답이 하나만 와도 진행한다. 나머지는 입력 자료의 성격으로 추정하고, 추정한 사실을 밝힌다.

### 3단계: 배정하고 근거를 밝힌다

> `report-monitoring`으로 진행하겠습니다. 월 단위 실적 데이터에 상급 기관 제출이 겹치므로 4단계 구조(현황 요약·주요 이슈·조치 사항·다음 달 계획)가 맞습니다. 다른 유형을 원하시면 말씀해 주세요.

배정 근거를 한 문장으로 남긴다. 사용자가 유형을 바꾸면 되묻지 않고 즉시 전환한다.

경계가 갈리는 사례(주간인데 실적 중심, 회의록인데 결과 보고 성격 등)는 `references/routing-table.md`를 읽고 판단한다.

## 인계 프로토콜

배정한 스킬을 Skill 도구로 호출하고, 아래를 함께 넘긴다.

1. 사용자가 준 원본 입력 (요약하지 않고 그대로)
2. 판별 결과 — 주기·목적·제출처
3. 공용 기준 적용 지시 — `references/report-standards.md`
4. 저장 포맷 요청이 있으면 그 값

인계 후에는 라우터가 개입하지 않는다. 개별 스킬의 워크플로우가 끝까지 진행한다.

## 준비 중 유형 요청 시

준비 중인 5종(daily·annual·trip·incident·result)을 요청받으면 우회하지 않고 상태를 먼저 밝힌 뒤, 가장 가까운 스킬로 임시 대응한다.

| 요청 | 임시 대응 | 보정 |
|---|---|---|
| 일일 보고 | `report-weekly` | 기간을 하루로, 4블록을 3블록으로 축소 |
| 분기·연간 결산 | `report-monitoring` | 기간 확장, "다음 달 계획"을 "차기 계획"으로 |
| 출장 보고 | `meeting-minutes` | 개요·결정·액션 구조에 방문지·경비 항목 추가 |
| 이슈·장애 보고 | `report-monitoring` | 4단계를 경위·원인·조치·재발 방지로 치환 |
| 사업 결과 보고 | `research-report` | 5섹션을 개요·추진 실적·성과·정산·향후 계획으로 치환 |

임시 대응임을 결과물 말미에 표기한다.

## 공용 기준

10종 전부가 아래 기준을 공유한다. 개별 스킬은 차이점만 정의한다.

| 기준 | 파일 | 핵심 |
|---|---|---|
| 작성 규칙 | `references/report-standards.md` | 문체·수치 근거·금지어·AI 흔적·개인정보 |
| 저장 규칙 | `references/output-formats.md` | 포맷 선택·파일명·docx/hwpx 스킬 연계 |

개별 스킬을 단독으로 내려받아 쓰는 경우 이 파일들이 없을 수 있다. 그때는 각 스킬에 포함된 최소 규칙으로 진행하고, 전체 기준이 필요하면 `report-suite` 폴더를 함께 올리도록 안내한다.

## 완성 조건

- 유형을 배정했고 근거를 한 문장으로 밝혔는가
- 준비 중 유형이면 상태를 먼저 밝혔는가
- 원본 입력을 요약·변형하지 않고 그대로 넘겼는가
- 라우터가 보고서 본문을 직접 쓰지 않았는가
