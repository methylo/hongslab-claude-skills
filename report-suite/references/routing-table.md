# 유형 판별표

라우터가 유형을 정하지 못할 때 읽는다.

## 판별 축

| 축 | 질문 | 값 |
|---|---|---|
| 주기 | 언제 쓰는 보고인가 | 정기(일일·주간·월간·분기·연간) / 사건 발생 시 / 사업 종료 시 / 필요할 때 |
| 목적 | 무엇을 하려는 보고인가 | 진행 공유 / 실적·성과 / 경위 설명 / 근거 제시 / 대외 공지 |
| 제출처 | 누가 읽는가 | 내부 팀 / 상급자 / 상급 기관·발주처 / 불특정 다수 |

세 축이 모두 같은 곳을 가리키면 배정한다. 갈리면 **제출처를 우선**한다. 제출처가 양식을 결정하기 때문이다.

## 판별 트리

```
정기 보고인가?
├─ 예 → 주기는?
│      ├─ 하루      → report-daily
│      ├─ 한 주     → report-weekly
│      ├─ 한 달     → report-monitoring
│      └─ 분기·연간 → report-annual
└─ 아니오 → 계기는?
       ├─ 회의를 했다        → meeting-minutes
       ├─ 현장에 다녀왔다    → report-trip
       ├─ 문제가 발생했다    → report-incident
       ├─ 사업이 끝났다      → report-result
       ├─ 조사·분석이 필요하다 → research-report
       └─ 대외 공지·모집이다  → chungcheong-report
```

## 경계 사례

| 상황 | 배정 | 이유 |
|---|---|---|
| 주간 보고인데 실적 수치 분석이 중심 | `report-monitoring` | 주기보다 목적이 무겁다. 기간만 한 주로 조정 |
| 월간 보고인데 내부 공유용 짧은 진행 상황 | `report-weekly` | 분석 없는 진행 공유는 경량 양식이 맞다 |
| 회의를 했지만 결과물이 사업 결과 정리 | `report-result` | 회의는 계기일 뿐 산출물이 결과 보고 |
| 출장을 갔고 그 자리에서 회의를 했다 | `report-trip` + 회의록 별첨 | 두 건으로 분리한다. 한 문서에 섞지 않는다 |
| 장애가 있었고 월간 보고에도 넣어야 한다 | `report-incident` 먼저 | 경위 보고를 쓴 뒤 월간 보고에 요약 인용 |
| 리서치 결과를 공공기관에 제출 | `research-report` → `.hwpx` 변환 | 내용은 분석형, 포맷만 양식형 |
| 공고문·모집 안내 | `chungcheong-report` | 보고가 아니라 대외 공지지만 양식이 같다 |

## 오배정 교정

작업 도중 유형이 틀렸다고 판단되면 즉시 알린다. 쓰던 내용은 버리지 않는다.

> 진행하다 보니 `report-weekly`보다 `report-monitoring`이 맞습니다. 실적 수치가 중심이고 상급 기관 제출이기 때문입니다. 지금까지 정리한 내용을 그대로 옮겨 4단계 구조로 다시 배치할까요?

사용자가 원래 유형을 고수하면 그대로 진행한다. 판단은 사용자 몫이다.

## 라우터를 거치지 않아도 되는 경우

사용자가 스킬명을 직접 부르거나(`report-weekly로 정리해줘`) 유형 키워드가 명확하면 라우터를 건너뛰고 해당 스킬로 바로 간다. 확인 질문을 반복하지 않는다.
