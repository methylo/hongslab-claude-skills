# write-content 출력 규칙 (Output Rules)

이 파일은 write-content 스킬의 단계별 산출물 명세와 포맷 규칙을 정의한다. SKILL.md의 각 Step에서 산출물을 만들기 직전에 참조한다.

## 산출물 기본 원칙

- 모든 단계의 기본 산출 형식은 대화창 텍스트다
- 파일(.docx/.md) 생성은 사용자가 명시 요청할 때만 수행한다
- 최종 산출물의 기본값은 기본본(페이스북·카카오톡 게시용 평문)이다

## 단계별 산출물 명세

### Step 1 산출물 — 프로파일 확인 요약

- 형식: 대화창 텍스트
- 기본 진행: 적용한 기본 프로파일(독자·채널·유형·포맷)을 요약 1줄로 제시
- 예외 진행: 목적·독자·채널·콘텐츠 유형 4가지 항목 요약
- 사용자 확인 후 Step 2 진입

### Step 2 산출물 — 아웃라인

- 형식: 대화창 텍스트 (기본) / 요청 시 `outline.docx`
- 내용: 유형별 구조에 따른 소제목 위계
- 사용자 확인 후 Step 3 진입

### Step 3 산출물 — 초안

- 형식: 대화창 텍스트 (기본)
- 기본본 대상 글은 평문 규칙(`publish-format.md`)을 적용한 상태로 제시한다
- 명시 요청 시: `draft.docx` 또는 `draft.md`
- 필수 구성: 출력 슬롯 템플릿(칼럼형 4슬롯 또는 문서형 5슬롯)을 모두 채운다. 슬롯을 건너뛰거나 순서를 바꾸지 않는다
- 자가 점검 전 항목을 통과한 뒤 출력
- 사용자 확인 후 Step 4 진입

### Step 4 산출물 — 점검 리포트 + 수정본

- 점검 리포트: 5가지 영역(구조·문장·스타일·채널·발행 포맷)을 표 형태로 제시
- 수정본: 전체 텍스트 + 하단에 변경 요약 박스

변경 요약 포맷:

```
**주요 변경 사항:**
- 구조: (변경 내용)
- 문장: (변경 내용)
- 스타일: (변경 내용)
- 채널·포맷: (변경 내용)
```

### Step 5 산출물 — 최종 완성본

| 산출물 | 형식 | 생성 조건 |
|--------|------|----------|
| **기본본** | 대화창 코드 블록(```) 안의 평문 | 항상 (기본값) |
| 확장본 (블로그) | 대화창 마크다운 텍스트 | 사용자 요청 시 |
| `final.docx` / `final.md` | 파일 | 명시 요청 시에만 |

- 기본본은 복사 후 페이스북·카카오톡에 그대로 게시하는 상태여야 한다. 발행 포맷 자가 점검(`publish-format.md`)을 통과한 뒤 출력한다
- 제목: 후보 3~5개 제시 후 사용자 선택. 기본본에서 제목을 첫 줄로 넣을지, 생략할지 사용자에게 확인한다
- 확장본은 `publish-format.md`의 확장본 변환 규칙을 따른다. sshong.com SEO 발행은 write-blog로 연계한다
- 문서 파일 생성 전 반드시 docx 스킬(SKILL.md)을 읽고 따른다

## 파일명·포맷 규칙 (파일 요청 시)

| 단계 | 파일명 | 비고 |
|------|--------|------|
| Step 2 | `outline.docx` | 요청 시 |
| Step 3 | `draft.docx` 또는 `draft.md` | 명시 요청 시 |
| Step 5 | `final.docx` / `final.md` | 명시 요청 시 |

## 산출물 총괄

| 단계 | 산출물 | 형식 |
|------|--------|------|
| Step 1 | 프로파일 확인 요약 | 대화창 텍스트 |
| Step 2 | 아웃라인 | 대화창 텍스트 / `outline.docx` (요청 시) |
| Step 3 | 초안 (기본본은 평문 적용) | 대화창 텍스트 / `draft.docx` (요청 시) |
| Step 4 | 점검 리포트 + 수정본 | 대화창 텍스트 |
| Step 5 | 기본본 (코드 블록 평문) | 대화창 텍스트 (기본) |
| Step 5 | 확장본 / 파일 | 요청 시 |

## 실행 모드 표기 (모든 산출 지점 공통)

Step 3·4·5의 모든 산출물, 그리고 `점검만 해줘` 요청의 점검 리포트 말미에 아래 한 줄을 붙인다. 성공·실패 모두 적는다.

```text
문체 기준: hong-voice-reference (1층·2층·3층 적용)
문체 기준: 폴백 최소 카드 (hong-voice-reference 호출 실패)
```

Step 4·5 수정본에는 그 앞줄에 AI 흔적 지수도 함께 적는다.

```text
AI 흔적 지수: 수정 전 N.N (등급) → 수정 후 N.N (등급)
```

**기본본(페북·카톡 평문)을 코드 블록으로 감싸 제공할 때는 이 두 줄을 코드 블록 밖에 둔다.** 사용자가 그대로 복사해 게시하는 영역이므로 안에 넣지 않는다.
