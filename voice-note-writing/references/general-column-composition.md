# 음성 범용 칼럼 직접 작성 기준

이 문서는 선택된 음성 Source Brief를 다른 범용 글쓰기 스킬에 넘기지 않고 `voice-note-writing` 안에서 완성하는 기준이다. 고정 템플릿이 아니라 음성에서 발견하고 사용자가 선택한 판단을 잃지 않기 위한 작성 순서다.

## 1. 길이 프로필

### `short_voice_column`

- 제목 제외 1,300~1,500자
- 중심 판단 하나, 실제 장면·관찰 중심
- 외부 자료는 없어도 성립할 때 기본값

### `standard_column`

- 제목 제외 2,000~3,000자 또는 사용자 지정 범위
- 대표 칼럼·아티클·긴 경험형 글
- 짧은 글의 문단을 늘리지 않고 확인된 근거·반론·적용 조건 가운데 필요한 층을 추가

### `channel_defined`

- 지정 채널 스킬의 분량과 형식을 따름
- 이 문서는 Source Brief와 핵심 원고의 판단 경계까지만 소유

길이만으로 장문을 선택하지 않는다. 사용자가 범위를 지정했거나 중심 판단을 설명하는 데 실제로 추가 층이 필요할 때만 `standard_column`을 쓴다.

## 2. 구조 설계

Source Brief의 `실제 문제·관찰 → 보존할 경험·표현 → 선택된 중심 판단` 사이 인과를 먼저 한 줄로 잇는다. 다음 요소 중 원문과 확인 근거에 있는 것만 사용한다.

- 직접 겪은 장면 또는 구체적인 불편
- 처음 가졌던 기대와 실제 결과의 어긋남
- 반복해서 돌아온 질문이나 망설임
- 판단을 보여 주는 실제 사례
- 확인된 외부 사실과 적용 한계
- 말한 뒤 달라진 생각, 행동 또는 현재 작업 방식

권장 흐름은 `구체적 출발점 → 어긋남이나 문제 → 중심 판단이 생긴 이유 → 필요한 사례·관찰·근거 → 현재 판단 또는 달라진 행동`이다. 원문에 없는 슬롯은 비워 둔다. 모든 글에 기대·반전·교훈을 만들지 않는다.

`standard_column`은 필요할 때만 다음 중 하나 또는 둘을 추가한다.

- 반대 근거나 예외
- 외부 자료가 확인한 범위
- 독자에게 적용되는 조건과 적용되지 않는 조건

완료 기준: 각 문단의 역할을 한 줄씩 적었을 때 모든 문단이 같은 선택 판단을 향하고, 빼도 되는 일반 설명이 구조의 중심을 차지하지 않는다.

## 3. 첫 초안

1. 원문에 실제 경험이나 문제 장면이 있으면 일반론보다 앞에 둔다.
2. 사용자 표현 중 판단의 온도를 가진 문장을 하나 이상 남긴다.
3. 사례는 원문에 있는 경험·관찰 또는 사실이 확인된 사례만 사용한다.
4. 설명 문단은 경험과 판단을 연결하는 데 필요한 만큼만 둔다.
5. 한두 개의 짧은 관찰 문단을 허용하고 모든 문단을 비슷한 길이로 맞추지 않는다.
6. 외부 근거는 저자의 판단을 증명하는 장식이 아니라 범위와 조건을 밝히는 데 사용한다.
7. 끝은 요약·교훈·독자 행동 촉구를 자동으로 붙이지 말고 현재 판단, 달라진 행동, 현재 상태 또는 실제로 남은 질문에서 멈춘다.
8. 전체 원고는 메인 작성자 한 명이 쓴다. 조사·독자·검토 에이전트가 문단별 완성문을 따로 작성해 조립하지 않는다.

분량이 부족하다고 원문에 없는 경험, 사례, 기능 설명을 보충하지 않는다. 필요한 재료가 부족하면 중심 판단을 더 구체화하거나 이미 있는 장면의 의미를 분명히 한다. `standard_column`에서 추가할 근거·반론·조건이 없으면 짧은 글을 억지로 늘리지 말고 사용자 지정 범위와 자료 부족을 알린다.

완료 기준: 초안만 읽어도 무엇을 겪었거나 관찰했고 그 결과 어떤 판단에 도달했는지 알 수 있으며, 원문에 없는 1인칭 경험이 없다.

## 4. 선택 방향과 원문 소유권 점검

초안을 판단 파일럿, Source Brief, 원본 전사문에 대조한다.

- 선택 판단이 제목·도입·본문·마무리에 유지되는가
- `rejected_directions`가 유사 표현으로 되살아나지 않았는가
- 제3자의 경험을 사용자의 경험으로 바꾸지 않았는가
- 작업 지시를 본문의 주장으로 넣지 않았는가
- 음성의 반복을 모두 지우면서 가장 직접적인 사용자 표현까지 없애지 않았는가
- 후반 정정 이전의 말을 최종 판단처럼 남기지 않았는가
- 불확실한 제품명·인명·수치가 사실처럼 확정되지 않았는가

하나라도 어긋나면 문장을 매끄럽게 만드는 대신 잠긴 선택과 원문에 맞게 되돌린다.

## 5. 문체 정본 적용

초안 뒤에는 `SKILL.md`의 `문체 기준 로드 (외부 정본 호출)` 절차를 따른다. `Skill` 도구로 `hong-voice-reference`를 호출해 반환된 `Base directory` 아래 세 층을 한 번에 읽고, 적용만 순서대로 한다. 이 스킬의 `references/`에는 문체 파일이 없다.

1. `01-voice.md` — 시선·논리·호흡을 조정한다.
2. `02-glossary.md` — 사용자가 잘 쓰지 않는 추상어와 낯선 표현을 바꾼다.
3. `03-anti-traces.md` — 과장, 빈 완곡어, 챗봇 말투, 지나치게 반듯한 결론을 문맥에 따라 걷어낸다. 판정은 §5-1을 따른다. 출현만으로 위반으로 세지 않는다.

이 단계는 문체 기준을 가져오는 과정이지 원고의 경험과 판단을 새로 해석하는 단계가 아니다.

완료 기준: 세 층을 현재 실행에서 읽었고, 수정 후에도 Source Brief의 선택 판단과 사용자 소유 경험이 그대로 남아 있다. 호출에 실패했으면 `SKILL.md` 하단 `문체 최소 카드`로 진행하고 산출물 말미에 문체 기준 한 줄로 밝힌다.

## 6. 제목과 최종 분량

제목은 본문을 다 쓴 뒤 정한다.

- 선택 판단을 직접 받되 모든 결론을 미리 설명하지 않는다.
- 원문에 없는 거대한 문제의식이나 과장을 추가하지 않는다.
- `~하는 법`, `~해야 하는 이유`를 기계적으로 붙이지 않는다.
- 블로그처럼 채널이 제목 규칙을 소유하면 해당 채널 계약을 따른다.

제목을 제외한 본문 글자 수를 `scripts/count.py`로 측정한다. 범위와 목표치는 그 스크립트의 `PROFILES`가 단일 기준이다.

- `short_voice_column`: 1,300~1,500자 (목표 1,400)
- `standard_column`: 2,000~3,000자 또는 사용자 지정 범위 (목표 2,400)
- `channel_defined`: 채널 계약

범위를 넘으면 반복 설명부터 줄인다. 범위보다 짧으면 새 사례를 만들지 말고 경험·관찰·근거와 판단의 연결이 생략되었는지 확인한다.

완료 기준: 제목과 마지막 문단이 같은 선택 판단을 가리키고, 본문이 선택된 길이 프로필을 충족한다.

## 금지되는 기본 경로

```text
voice-note-writing Source Brief
→ write-content
→ 범용 칼럼
```

채널 미지정, `범용 칼럼`, `일반 글` 요청에서는 위 경로를 사용하지 않는다. 블로그·페이스북·브런치·에세이·책 원고처럼 별도 채널이 명시된 경우에만 선택 판단·근거 범위·중복 제외 목록을 잠근 Source Brief를 해당 채널 스킬로 인계한다.
