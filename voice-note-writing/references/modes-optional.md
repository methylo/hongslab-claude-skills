# 조건부 모드와 운영 규칙

> **조건부 절.** 진입 조건에 걸릴 때만 읽는다. 조건은 `SKILL.md`에 있다.

---

## 부분 개선 추천과 적용 모드

사용자가 완성 원고에서 `어떤 부분을 개선하면 좋은지`, `세 가지만 추천해줘`처럼 제한된 퇴고 의견을 요청하면 전체 원고를 다시 쓰기 전에 우선순위가 높은 지점만 고른다.

각 추천은 세 요소를 함께 제공한다.

1. 원고의 정확한 현재 문장 또는 문단
2. 그대로 교체할 수 있는 **완성된 추천 문장**
3. 왜 바꾸는지에 대한 한두 문장의 근거

추상적인 조언만 주지 않는다. `도입을 구체화한다`, `마무리를 줄인다`에서 멈추지 말고, 사용자가 바로 비교하고 선택할 수 있는 완성 문장을 제시한다. 추천 개수가 지정되면 가장 영향이 큰 항목만 그 수에 맞춰 고른다.

우선 검토 후보는 다음과 같지만 고정 체크리스트로 사용하지 않는다.

- 개념 설명으로 시작하는 도입을 실제 행동·장면으로 바꿀 지점
- `과정이 쌓였다`, `차이가 커졌다`처럼 추상적인 설명을 실제 행동과 전후 변화로 바꿀 지점
- 본문을 다시 요약하는 마지막 문단을 현재 상태·다음 행동으로 줄일 지점

사용자가 추천 문장을 승인해 `적용해줘`라고 하면 조각만 다시 보여주지 않고 승인된 교체안을 **원고 전체에 반영한 완성본**을 제공한다. 이때 추천 문장과 앞뒤 문단의 연결, 같은 의미의 중복, 승인 문구의 판단 유지, 분량 조건 충족을 확인한다.

분량이 줄었다는 이유로 새 경험이나 사례를 만들지 않는다. 필요한 경우 원문에 이미 있는 판단·행동의 연결만 보강한다.

## 채널 지정 시 선택적 인계

> **인계해도 문체 3층은 이 스킬이 책임진다.** 인계 대상 채널 스킬(`write-blog`·`write-facebook`·`write-essay`·`book-writing-pro`)은 `hong-voice-reference`를 호출하지 않는다. 채널 스킬이 원고를 낸 뒤, 이 스킬로 돌아와 Step 9(3층 적용)와 Step 10(역점검)을 실행한다. 그렇게 하지 않으면 정본 문체가 적용되지 않은 원고가 나간다. 인계 시 Source Brief에 `문체 3층 미적용 — voice-note-writing Step 9 필요`를 명시한다.


사용자가 결과 채널을 명시한 경우에만 Source Brief를 해당 스킬로 넘기고 그 채널의 구조·분량을 우선한다.

| 지시 | 인계 대상 |
|---|---|
| 범용 칼럼·일반 글·채널 미지정 | 인계 없음 — `voice-note-writing` 안에서 완성 |
| sshong.com 블로그 | `write-blog` |
| 페이스북 | `write-facebook` |
| 에세이 | `write-essay` |
| 책 원고·챕터 | `book-writing-pro` 또는 해당 책쓰기 스킬 |

인계 대상 스킬이 현재 환경에 설치돼 있는지 먼저 확인한다. 없는 스킬로 넘기지 않고, 이 스킬 안에서 완성한 뒤 채널 규칙을 적용하지 못했음을 한 줄로 알린다.

인계 후에도 원본 잠금, 선택된 중심 판단, 폐기한 방향, 경험 소유권, 전사 불확실성, 확인된 근거 범위는 이 스킬의 Source Brief를 기준으로 유지한다. 채널 스킬이 원본을 일반적인 메모처럼 다시 해석하거나 별도의 중심 판단을 만들지 않게 한다. 채널 작성자는 구조·분량·검색·도입 형식만 소유하며 **전체 원고를 쓰는 주 작성자는 하나다.**

## 저장 규칙

기본값은 대화창 출력이다. 파일 저장은 사용자가 명시적으로 요청했을 때만 실행한다.

이 스킬은 저장 위치를 알지 못한다. 폴더 구조를 추측하거나 기본 경로를 만들어 쓰지 않는다.

- 사용자가 경로를 지정하면 그 경로에 저장한다.
- 경로 없이 `저장해줘`라고만 하면 어디에 저장할지 한 번 묻는다. 답을 받기 전에는 파일을 만들지 않는다.
- 파일명은 사용자가 지정한 규칙을 따른다. 지정이 없으면 제목을 그대로 쓰고 `제목.md`로 만든 뒤 파일명을 알린다.
- frontmatter가 필요하면 `date: YYYY-MM-DD`(KST)만 넣는다.
- 별도 퇴고 요청이 없으면 저장 과정에서 제목·본문을 임의로 고치지 않는다.
- 완료 보고는 파일명과 저장 경로만 짧게 한다.

세 선택지(`저장하기 / 조금 고치기 / 이번에는 저장하지 않기`)를 제시하는 규칙은 `SKILL.md`의 기본 출력 절에 있다. 이 문서는 사용자가 저장을 고른 뒤의 경로·파일명 처리만 소유한다.

## 선택지를 묻는 방법

사용자에게 선택을 받아야 하는 지점은 셋이다. 주제 선택(Step 5), 판단 파일럿 선택(Step 7.5), 완성 뒤 저장 여부.

- `AskUserQuestion`을 쓸 수 있으면 그것으로 묻는다. 선택지는 3개를 넘기지 않는다.
- 도구를 쓸 수 없는 환경이면 번호 목록으로 대체한다. `1. … / 2. … / 3. …` 형식으로 쓰고 번호로 답해 달라고 한 줄 덧붙인다.
- 어느 쪽이든 같은 선택지를 본문에 두 번 나열하지 않는다.
- 답을 받기 전에는 다음 단계로 넘어가지 않는다.

## Personalization Loop

이 스킬은 자기 파일을 고치지 못한다. 스킬 폴더는 읽기 전용 사본이다. 사용자 교정은 다음 경로로만 남는다.

| 교정 종류 | 처리 |
|---|---|
| 이번 음성에만 해당하는 말실수·임시 주제 | 현재 세션에서만 적용 |
| 안정적인 사용자 취향 | 메모리에 저장 |
| 반복되는 음성 오인식 | 세 번 이상 반복될 때 사전 항목 문안을 제안하고, 사용자가 스킬을 갱신하도록 안내 |
| 여러 글에서 확인된 어휘·문체 교정 | `hong-voice-reference`의 해당 층 수정을 제안. 정본 갱신은 그 스킬 재패키징으로만 한다 |

한 번의 수정으로 규칙을 만들지 않는다. 같은 문제가 여러 작업에서 반복되거나 사용자가 기준화를 요청했을 때만 제안한다. 제안은 한 줄로 하고 원고 뒤에 붙인다.

## Change Verification

트리거, 기본 분량, 실행 모드, 판단 파일럿, 근거 관문, 출력 형식, 저장 정책, 채널 인계를 수정한 뒤에는 `references/verification-protocol.md`의 회귀 검증 4갈래를 실행하고, 결과를 그 문서 11항 형식으로 남긴다. 실패를 성공처럼 요약하지 않는다.

```bash
python3 scripts/validate.py
```
