# 비정형 음성 전사문 작업 예시

이 문서는 처리 형태를 보여주는 예시다. 전체 원고의 고정 템플릿이 아니며, 사용자의 실제 경험과 현재 요청을 우선한다.

## 예시 1. 기능 설명과 작업 지시가 섞인 음성

### 전사문 일부

> 아직 많은 사람들이 클라우드 스킬에 대해 잘 모르고 있다. 어떤 스킬이 있고 장점이 무엇인지, 어떻게 활용하는지 생각보다 많이 모른다. 스킬을 더 쉽게 쓰고 내가 가진 일에 바로 응용할 수 있게 사례도 좀 넣어 주고, 만드는 것도 있지만 결국 나에게 최적화하는 방법이 필요한 것 같다.

### 발화 분해

- 관찰: 많은 사람이 클로드 스킬을 어렵게 느끼고 활용법을 모른다.
- 판단: 만드는 법보다 기존 스킬을 자기 일에 맞게 고쳐 쓰는 방법이 먼저다.
- 작업 지시: 쉬운 설명, 실제 사례 추가, 기능 설명 보강.
- 전사 교정: `클라우드 스킬`은 같은 대화의 Claude 문맥에서 `클로드 스킬`로 교정.
- 후속 글감: 스킬의 기본 기능, 기존 스킬 수정법, 개인화 사례는 각각 별도 글이 될 수 있다.

### 중심 의도

> 이 글은 스킬이 어렵게 느껴지는 문제를 통해, 처음부터 복잡하게 만들기보다 기존 스킬을 자기 일에 맞게 고쳐 쓰는 법을 먼저 익혀야 한다는 판단을 말한다.

### Source Brief 핵심

```text
추출한 주제: 클로드 스킬을 내 일에 맞게 고쳐 쓰는 법
중심 판단: 스킬은 만드는 기술보다 반복 작업의 기준을 개인화하는 방법부터 익혀야 한다.
보존할 표현: “내가 가진 일에 바로 응용한다”, “나에게 최적화한다”
글쓰기 지시: 입문자용 설명, 사례 비중 높임, 기능 나열 최소화
권장 결과: 1,300~1,500자 범용 칼럼
```

## 예시 2. 스킬 제작 요청 자체가 주제인 음성

### 전사문 일부

> 주로 글을 쓰는데 음성으로 이야기하고, 어떤 주제가 있는 것도 아니고 지금처럼 주저리주저리 말한 걸 가지고 글을 쓰는 스킬을 따로 만들고 싶다.

### 발화 분해

- 경험·작업 방식: 글을 쓸 때 먼저 음성으로 생각을 말한다.
- 문제: 말하기 전에 주제와 구조가 정해져 있지 않다.
- 판단: 음성 전사문에서 주제를 먼저 찾는 전용 스킬이 필요하다.
- 작업 지시: 현재 입력을 분석해 스킬을 추천한다.

### 중심 의도

> 이 글은 주제 없이 말하는 사용자의 작업 방식에서 출발해, 음성 글쓰기에서는 문장 정리보다 중심 생각을 발견하는 앞단 작업이 먼저라는 판단을 말한다.

### Source Brief 핵심

```text
추출한 주제: 주제 없이 말한 음성을 글로 바꾸는 방법
중심 판단: 음성 글쓰기는 문장을 다듬기 전에 반복 속 중심 생각을 찾아야 한다.
보존할 경험: “어떤 주제가 있는 것도 아니고 지금처럼 주저리주저리 말한다”
글쓰기 지시: 스킬의 역할과 기존 범용 칼럼 스킬의 연결을 설명
권장 결과: 개념형 범용 칼럼 또는 스킬 설계 문서
```

## 실패 예시

### 실패 1. 첫 문장을 주제로 고정

```text
잘못된 주제: 많은 사람이 스킬을 모른다.
```

발화 전체에서는 `나에게 최적화하는 방법`이 반복되고 후반에 강화되었다. 첫 문장은 문제 상황이고, 중심 판단은 개인화 방법에 있다.

### 실패 2. 작업 지시를 본문에 삽입

```text
스킬을 설명할 때는 사례 농도를 높여야 한다.
```

이 문장은 사용자가 AI에게 준 편집 요청이다. 글의 주장이 아니다.

### 실패 3. 일반론으로 과도하게 정리

```text
음성 기반 콘텐츠 제작은 현대적인 생산성 향상 방식이다.
```

원문에는 생산성이나 현대성에 관한 판단이 없다. `주제를 먼저 정하지 않고 말한다`는 실제 작업 방식을 중심에 둔다.

## 예시를 추가하는 기준

- 사용자가 최종 원고를 승인했거나 반복 사용 의사를 밝힘
- 전사문과 최종 글 사이의 변화가 특정 처리 규칙을 보여줌
- 기존 예시와 다른 실패 유형 또는 판단 방식이 있음
- 개인 정보와 일회성 프로젝트 상태를 제거함

새 예시를 추가할 때는 전체 대화가 아니라 `전사문 일부 → 분류 → 중심 의도 → Source Brief 핵심`만 보존한다.
