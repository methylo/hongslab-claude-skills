# 리서치 보고서 워크플로우 (Research Report Workflow)

강의·교육 자료의 근거가 되는 리서치/분석 보고서를 고정 템플릿으로 반복 생성하는 프로세스.
이 보고서는 강의 기획, 교육 커리큘럼 설계, 콘텐츠 제작의 사전 단계에서 주제의 현황·근거·방향을 정리하는 데 사용한다.

## 보조 파일 안내

| 파일 | 용도 | 참조 시점 |
|------|------|-----------|
| `scripts/research-report-template.js` | .docx 파일 생성 템플릿 (디자인 토큰·스타일·레이아웃 내장) | Step 3 (최종 출력) |
| `../report-suite/references/report-standards.md` | 보고서 10종 공용 작성 기준 (문체·수치·금지어·개인정보) | Step 2 초안 작성 전 |
| `../report-suite/references/output-formats.md` | 저장 포맷·파일명 규칙 | Step 3 최종 출력 시 |

---

## 전체 흐름

```
Step 1: 입력 정리 → Step 2: 섹션별 초안 작성 → Step 3: 리라이팅·최종 출력
```

사용자 상태에 따라 적절한 단계부터 시작한다.
- 리서치 주제만 있음 → Step 1부터 (필요 정보를 질문으로 수집)
- 주제·범위·자료가 있음 → Step 2부터
- 초안이 있음 → Step 3부터

---

## 공통 원칙

### 보고서 성격

이 보고서는 **강의·교육 자료의 근거 문서**다. 읽는 사람은 강의를 기획하는 본인(홍작가) 또는 교육 관련 의사결정자다. 보고서의 목적은 특정 주제에 대해 "현재 상황이 무엇이고, 무엇이 발견되었으며, 교육적으로 어떤 시사점이 있는가"를 구조적으로 정리하는 것이다.

외부 발표용 보고서가 아니다. 내부 참고 자료로서의 실용성을 우선한다. 화려한 수사보다 근거의 정확성과 논리적 연결이 중요하다.

### 문체·금지어

공용 기준(`../report-suite/references/report-standards.md`)을 상속한다. 리서치 보고서에만 추가로 적용하는 항목은 아래와 같다.

- 문장은 18~25단어 내외. 한 문장에 하나의 정보만 담는다
- 문단은 3~5문장. 능동형을 기본으로 한다
- 감정적 표현·감탄형 문장을 쓰지 않는다. 분석적 톤을 유지한다
- **추측 표현 금지**: ~할 수 있다, ~일 수 있다, ~라고 볼 수 있다 → 단정형 서술
- **불필요한 연결어 금지**: 전반적으로 볼 때, 일반적으로 말하면, 결과적으로
- **추상 명사 중심 문장 지양**: 중요성·필요성·가능성 → 동사 중심 문장으로 전환

공용 기준 파일이 없으면 위 항목에 더해 과장형 형용사(혁신적인·획기적인·완벽한)와 모호한 부사(매우·상당히·쉽게)를 금지어로 적용한다.

### 문장 품질 기준 (GOOD/BAD 예시)

| BAD (금지) | GOOD (기준) |
|-----------|------------|
| AI 글쓰기 도구 시장이 빠르게 성장하고 있다 | AI 글쓰기 도구 시장은 2024년 12억 달러에서 2025년 28억 달러로 133% 성장했다 (Grand View Research, 2025) |
| 이 기술은 매우 혁신적인 접근 방식을 제공한다 | 이 기술은 입력 1회로 초안·수정·최종본 3단계를 자동 분기한다 |
| 다양한 교육 현장에서 활용 가능성이 높다 | 기업 교육(삼성SDS), 대학 강좌(서울대 AI 글쓰기), 자격증 과정(KIRD) 3곳에서 도입 사례가 보고되었다 |

### 근거 표기 원칙

- 모든 사실 주장에는 출처를 표기한다
- 본문 내 인라인 출처: `(출처명, 연도)` 또는 `(출처명, 날짜)` 형태
- 통계·수치에는 반드시 출처와 시점을 명시한다
- 출처가 불확실한 정보는 `[확인 필요]` 마커를 삽입한다
- 웹 검색 결과를 활용할 경우, URL과 접근 일자를 부록에 기록한다

### 출력 슬롯 템플릿 (보고서는 반드시 이 구조를 따른다)

모든 리서치 보고서는 아래 슬롯을 동일한 순서로 포함한다. **슬롯을 건너뛰거나 순서를 바꾸지 않는다.**

```
[타이틀 페이지] ← RESEARCH REPORT 라벨, 제목, 부제, 메타 정보
[목차 페이지] ← CONTENTS, H1~H2 범위 자동 생성
[섹션1: 요약] ← 배경 1~2문장 → 핵심 발견 2~3문장 → 시사점 1~2문장 (300~500자)
[섹션2: 배경 및 문제 정의] ← 왜 조사하는가 → 현재 상황 → 핵심 질문 (500~1,000자)
[섹션3: 핵심 발견] ← 발견 3~5개, 각각 사실+근거+의미 (1,000~2,000자)
[섹션4: 시사점 및 제언] ← 교육적 시사점 → 콘텐츠 방향 제언 (500~1,000자)
[섹션5: 출처 및 부록] ← 인라인 출처 전체 정리
```

**슬롯 간 정합성 규칙:**
- [섹션1: 요약]은 [섹션3]과 [섹션4]를 모두 작성한 뒤 마지막에 쓴다
- [섹션4: 시사점]은 반드시 [섹션3: 핵심 발견]에서 도출한다. 발견에 없는 시사점을 추가하지 않는다
- [섹션5]에는 본문 인라인 출처를 모두 포함한다

## Step 1: 입력 정리

사용자로부터 아래 정보를 수집한다. 이미 대화에 포함된 내용은 다시 묻지 않는다.

### 필수 입력

아래 3개 항목이 확인되지 않으면 Step 2로 넘어가지 않는다. **추측으로 채우지 않고 사용자에게 질문한다.**

| 항목 | 설명 | 누락 시 질문 |
|------|------|-------------|
| 리서치 주제 | 무엇을 조사하는가 | "어떤 주제를 조사할까요?" |
| 리서치 목적 | 이 보고서를 왜 쓰는가 — 어떤 강의·교육에 활용할 것인가 | "이 보고서를 어떤 강의나 교육에 활용하시나요?" |
| 분석 범위 | 시간 범위, 지역, 대상 기술/시장/현상 등 조사 경계 | "조사 범위를 알려주세요 (시간, 지역, 대상)" |

### 선택 입력

| 항목 | 설명 |
|------|------|
| 참고 자료 | 이미 수집한 기사, 논문, 보고서, URL 등 |
| 핵심 질문 | 이 리서치에서 반드시 답해야 할 질문 2~3개 |
| 비교 대상 | 비교 분석이 필요한 도구·기술·방법론 등 |
| 관련 강의 | 이 보고서가 근거가 될 강의명 또는 커리큘럼 |

### 입력 정보가 부족할 때

부족한 항목이 있으면 한 번에 모아서 질문한다. 항목별로 따로 묻지 않는다.

```
리서치 보고서를 작성하려면 아래 정보가 필요합니다.

1. 리서치 목적 (어떤 강의·교육에 활용하는가):
2. 분석 범위 (시간, 지역, 대상):
3. (기타 부족한 항목)

나머지는 제공해주신 내용에서 정리하겠습니다.
```

### 산출물

수집된 정보를 아래 형식으로 요약 정리해 사용자에게 제시한다. 확인 후 Step 2로 진행한다.

```
## 리서치 개요
- 주제:
- 목적:
- 범위:
- 핵심 질문:
- 활용 강의:
```

## Step 2: 섹션별 초안 작성

### 작성 순서

1. **배경 및 문제 정의** — 리서치의 맥락을 설정한다
2. **핵심 발견** — 조사 결과를 구조화한다
3. **시사점 및 제언** — 발견에서 교육적 함의를 도출한다
4. **요약** — 위 섹션을 모두 쓴 뒤, 전체를 압축한다
5. **출처 및 부록** — 본문에서 인용한 모든 출처를 정리한다

요약을 마지막에 쓰는 이유: 본문 섹션을 먼저 완성해야 요약에서 핵심 발견과 시사점을 정확하게 압축할 수 있다.

### 섹션별 작성 규칙

#### 1. 요약 (Executive Summary)

- 분량: 300~500자 (A4 반 페이지 이내)
- 구성: 리서치 배경 1~2문장 → 핵심 발견 2~3문장 → 시사점 1~2문장
- 이 요약만 읽어도 보고서의 결론과 방향을 파악할 수 있어야 한다
- 본문에 없는 내용을 요약에 포함하지 않는다

#### 2. 배경 및 문제 정의

- 분량: 500~1,000자
- 구성:
  - **왜 이 주제를 조사하는가** — 교육·강의 기획 맥락에서의 필요성
  - **현재 상황** — 해당 분야의 현황을 데이터·사례로 기술
  - **문제 또는 질문** — 이 리서치가 답하려는 핵심 질문을 명시
- 현황 기술 시 시점을 명확히 한다 ("2026년 3월 기준" 등)
- 배경 설명이 길어지면 소제목(H2)으로 구분한다

#### 3. 핵심 발견 (Key Findings)

- 분량: 1,000~2,000자 (보고서의 핵심 본문)
- 구성: 발견 항목을 3~5개로 구조화한다
- 각 발견 항목의 형식:

```
### 발견 N: [발견 내용을 요약하는 소제목]

(설명 2~4문단)
- 무엇이 발견되었는가 (사실)
- 어떤 데이터·사례가 이를 뒷받침하는가 (근거)
- 기존 인식과 무엇이 다른가 (의미)
```

- 각 발견에는 반드시 근거(데이터, 사례, 출처)를 포함한다
- 비교 분석이 있으면 표로 정리한다
- 표 캡션은 "▶ [표 제목]" 형태로 작성한다

#### 4. 시사점 및 제언

- 분량: 500~1,000자
- 구성:
  - **교육적 시사점** — 핵심 발견이 강의·교육 기획에 주는 의미
  - **콘텐츠 방향 제언** — 이 발견을 바탕으로 어떤 강의/콘텐츠를 설계할 것인가
  - **추가 조사 필요 사항** (선택) — 후속 리서치가 필요한 영역
- 시사점은 반드시 섹션 3의 핵심 발견에서 도출한다. 발견에 없는 시사점을 추가하지 않는다
- 제언은 구체적 행동 단위로 기술한다
  - ❌ "AI 글쓰기 교육이 필요하다"
  - ✅ "프롬프트 설계 중심의 3시간 실습 모듈을 신규 개설한다"
- 제언이 3개 이상이면 표로 정리한다

#### 5. 출처 및 부록

- **출처 목록**: 본문에서 인용한 모든 자료를 정리

```
[출처명] 제목 (날짜). (접근일: YYYY-MM-DD)
```

- **부록** (선택): 본문에 포함하기엔 상세하지만 참고가 필요한 데이터, 비교표, 용어 정의 등

### 웹 검색 활용

리서치 보고서는 최신 정보가 핵심이다. Step 2 진행 시:

- 사용자가 제공한 자료만으로 부족하면, 웹 검색을 적극 활용한다
- 검색 시 학술 자료, 공식 보고서, 신뢰할 수 있는 매체를 우선한다
- 검색 결과의 출처와 접근 일자를 섹션 5에 반드시 기록한다
- 검색 결과가 상충할 경우, 양쪽을 모두 기술하고 판단 근거를 제시한다

### 초안 자가 점검 (출력 전 반드시 실행)

초안 작성 완료 후, 아래 항목을 확인한다. 해당 항목이 있으면 수정한 뒤 출력한다.

- [ ] "혁신적인", "획기적인", "완벽한" 등 과장형 형용사 포함 여부
- [ ] "~할 수 있다" 추측 표현 포함 여부
- [ ] "매우", "쉽게", "빠르게" 등 모호한 부사 포함 여부
- [ ] 출처 없이 수치·통계를 기술한 곳이 있는가
- [ ] 슬롯 구조 이탈 여부 (섹션 순서 변경, 섹션 누락)
- [ ] [섹션4 시사점]이 [섹션3 핵심 발견]에서 도출되지 않은 내용을 포함하는가

### 초안 출력

초안은 대화창 텍스트로 제공한다. .docx 파일은 생성하지 않는다.
사용자가 "최종본", "파일로", "문서로" 등을 요청하면 Step 3 이후 파일을 생성한다.

---

## Step 3: 리라이팅·최종 출력

### 리라이팅 체크리스트

초안을 아래 기준으로 점검하고 수정한다.

**문장 품질**
- [ ] 금지어(과장 형용사, 모호 부사, 추측 표현) 제거
- [ ] 한 문장이 50자를 넘으면 분리 검토
- [ ] 단정형 서술 확인 ("~할 수 있다" → "~한다")
- [ ] 동일한 문장 구조·어미가 3회 이상 연속 반복되지 않는지 확인

**구조 일관성**
- [ ] 5개 섹션(요약, 배경/문제 정의, 핵심 발견, 시사점/제언, 출처 부록)이 모두 포함
- [ ] 섹션 번호 체계가 일관적
- [ ] 핵심 발견의 소제목이 행동·판단 중심인지 확인

**내용 정합성**
- [ ] 요약의 내용이 본문과 일치하는지 확인
- [ ] 시사점이 핵심 발견에서 도출된 것인지 확인 (근거 없는 시사점 제거)
- [ ] 본문의 모든 인라인 출처가 섹션 5에 포함되어 있는지 확인
- [ ] `[확인 필요]` 마커가 모두 해결 또는 명시적으로 표기되어 있는지 확인

**근거 품질**
- [ ] 통계·수치에 출처와 시점이 명시되어 있는가
- [ ] 출처의 신뢰도가 적절한가
- [ ] 상충하는 정보가 있을 경우 양쪽이 모두 기술되어 있는가

### .docx 파일 생성

## 사용자 요청별 대응

| 사용자 요청 | 실행 |
|-------------|------|
| "리서치 보고서 써줘" + 주제 | Step 1에서 부족 정보 확인 → Step 2 초안 |
| "~에 대해 조사해줘" + 강의 맥락 | Step 1에서 범위 확인 → 웹 검색 → Step 2 |
| "다듬어줘" + 기존 보고서 | Step 3 리라이팅만 수행. 분량·구조 유지 |
| "시사점 보강해줘" | 섹션 4만 수정. 나머지 섹션 유지 |
| "최종본 파일로" | 리라이팅 완료 후 템플릿으로 .docx 생성 |
| "발견 항목 추가해줘" | 섹션 3에 항목 추가. 요약·시사점도 연동 수정 |
| "출처 정리해줘" | 섹션 5만 재정리. 본문 인라인 출처와 대조 |

## 분량 통제 규칙

- **"다듬어줘" / "수정해줘"** = 원본의 문장 수·문단 수·전체 구조를 유지한 채 표현만 정리. 새로운 문장이나 문단을 추가하지 않는다
- **"보강해줘"** = 지정된 섹션에 한해 내용 추가를 허용. 미지정 섹션은 원본 유지
- **"추가해줘"** = 지정된 위치에 지정된 분량만 삽입
- 수정 결과물의 총 분량이 원본 대비 120%를 초과하면, 초과 사유를 사용자에게 먼저 확인

## 스킬 간 연계

### 이 스킬의 범위

이 스킬은 **리서치/분석 보고서**만 처리한다. 다른 보고서 유형은 `report-suite`가 판별해 배정한다.

- 주간 업무 보고 → report-weekly
- 월간 모니터링 → report-monitoring
- 회의록 → meeting-minutes
- 공공 표준 양식(.hwpx) → chungcheong-report

보고서 외 범위는 아래와 같다.
- 일반 글쓰기(블로그·뉴스레터·칼럼) → write-content
- 페이스북 글쓰기 → write-facebook
- sshong.com 블로그 글쓰기 → write-blog
- 브런치 글쓰기 → write-brunch
- 에세이(수필·산문) → write-essay
- 장편(책) 집필 → book-writing
- 강의 슬라이드 제작 → lecture-slides
- 강좌 소개 글 → write-course-intro

### 이 스킬의 산출물을 타 스킬로 보낼 때

이 보고서는 다른 스킬의 입력 자료로 활용된다. 주요 연계 패턴:

| 연계 대상 | 활용 방식 |
|----------|----------|
| lecture-slides | 보고서의 핵심 발견을 강의 슬라이드 콘텐츠로 변환 |
| write-blog | 보고서의 특정 발견을 블로그 글 주제로 확장 |
| write-facebook | 보고서의 시사점을 페이스북 인사이트 글로 변환 |
| book-writing | 보고서를 책 챕터의 근거 자료로 활용 |
| write-course-intro | 보고서의 배경·시사점을 강좌 도입부·교육특징에 반영 |
