# chungcheong-report

충청연수원·중소벤처기업진흥공단 표준 양식을 기반으로 임의의 입력 자료를 7섹션 구조의 한글(.hwpx) 보고서·공고문으로 변환한다.

**v2 (2026.05)**: 표 행 가변화·셀 컨텍스트 치환·무결성 자동 검증 통합. 보강 스크립트 없이 단일 실행으로 모든 자리표시자 처리.

## 공용 기준과의 관계

보고서 10종의 공용 기준(`../report-suite/references/report-standards.md`) 중 **개인정보·수치 근거·금지어·AI 흔적** 항목을 상속한다.

다만 **문체와 분량은 아래 양식 규칙이 우선한다.** 공공 표준 양식은 종결어미 `~합니다`체 또는 명사형을 쓰고 한 항목 80~95자를 채우므로, 공용 기준의 `~하였다`체·40자 규칙을 적용하지 않는다.

## 양식 규칙 (필수 4원칙)

1. **A4 우측 채움 + 3줄 이내** — 한 항목 80~95자 기준. 문장이 3줄 넘으면 분리하거나 표로 전환
2. **표 적극 활용** — 5줄 이상 나열되는 항목은 표 우선 검토
3. **계층 기호 + 들여쓰기 자동** — `□`(대제목) → `◦`(중제목) → `-`(세부) → `◈`(강조·유의) → `*`(각주)
4. **추진 배경은 등급 A 공공통계** — 통계청·관세청·산업통상자원부 등 정부 공식 자료 우선 인용

## 6단계 워크플로우

각 단계 완료 후 사용자 확인을 받는다. "그대로 진행" 선택 시 자동 추정값으로 진행한다.

### Phase 1. 입력 정리

사용자에게 받는 입력
- 참고 자료 (PDF·텍스트·메모, 1개 이상 / 없으면 직접 정보 입력)
- 사업명·문서 제목
- 보고서 종류 (모집 공고 / 추진 계획서 / 운영 보고 / 결과 보고)
- 핵심 사실 정보 (사업 기간·예산·대상·평가 방식)
- 분량 목표 (A4 페이지 수, 기본 5~7쪽)

자동 진단·보고 항목
- 입력 자료에서 추출한 사업 정보 요약
- 부족한 정보 목록 (사용자에게 1회 보강 질문)

### Phase 2. 추진 배경 통계 리서치

7섹션 중 추진 배경(섹션 1)은 별도 리서치 단계로 분리한다.

작업 내용
- 사업 주제에 맞는 정량 데이터 검색 (web_search 사용)
- 등급 A 출처 우선: 통계청 KOSIS, 관세청, 산업통상자원부, 한국은행
- 등급 B 보조: KDI·KIET 등 국책 연구기관
- 등급 C는 단독 인용 회피
- 수집한 수치는 출처·발표연도·식별번호와 함께 정리

산출 형태 (사용자 확인용)

```
| 인용 데이터 | 출처 | 발표연도 |
| --- | --- | --- |
| [수치 1] | 통계청 [통계명] | [YYYY] |
| [수치 2] | 관세청 [통계명] | [YYYY] |
```

### Phase 3. 7섹션 본문 작성

| 섹션 | 항목 | 작성 원칙 |
| --- | --- | --- |
| 머리말 | 기관명·공고번호·제목·안내문구·작성일자·발신 | `[기관명] 공고 제[YYYY-NN]호` 형식 |
| 1 추진 배경 | 추진 필요성·추진 목적 | Phase 2 통계 데이터를 4단 구조(현황→문제→필요성→출처)로 |
| 2 사업 개요 | 사업명·기간·예산·내용 | `□ 사업명 : [정식 명칭]` 한 줄 항목 |
| 3 지원 대상·규모 | 대상 구분표·신청 제외 | 4열 비교표 + `◈` 제외 대상 박스 |
| 4 진행 절차 | 단계 흐름표·신청 방법·제출 서류 | 5열 흐름표(1단계→5단계) |
| 5 평가 기준·가점 | 평가 항목 배점표·가점 사항 | 3열 배점표 (항목·배점·설명) |
| 6 유의 사항 | 중복 제한·포기 시 제재·일반 단서 | 모든 항목을 `◈`로 시작 |
| 7 문의처 | 총괄·운영 기관 연락처 | 3열 표 (기관·연락처·문의 내용) |

문체 규칙
- 종결어미 ~합니다체 기본 (공고문은 명사형·생략형도 허용)
- 축약형 금지 ("됐습니다" → "되었습니다")
- 금지어 0건: 혁신적인·획기적인·완벽한·매우·쉽게·빠르게·~할 수 있습니다 + 추상명사
- 추상 형용사·모호 부사 0건

### Phase 4. .hwpx 빌드

작업 흐름
1. `assets/blank_template.hwpx`를 작업 디렉토리에 복사 후 unzip
2. `Contents/section0.xml`의 자리표시자를 Phase 3 본문으로 치환 (v2: 표 행 가변화 + 무결성 자동 검증)
3. `scripts/pack_hwpx.py`로 다시 .hwpx로 패키징
4. 결과 파일명: `YYMMDD_[사업명]_[보고서종류].hwpx`

자리표시자 치환 규칙
- `[기관명]`, `[YYYY-NN]`, `[보고서·공고문 제목 입력]` 등 대괄호 토큰 모두 사실로 교체
- 표 행은 데이터 길이만큼 자동 복제 (지원대상·평가항목·문의처)
- 빌드 직후 무결성 검증 자동 실행 (결함 발견 시 종료 코드 1)

빌드 명령 예시

```bash
# 1. 작업 디렉토리 준비
WORK=$(mktemp -d)
unzip -q assets/blank_template.hwpx -d $WORK

# 2. section0.xml 편집 (v2 통합 스크립트 — 단일 실행)
python3 scripts/build_report.py \
  --work $WORK \
  --data report_data.json

# 3. .hwpx로 다시 패키징
python3 scripts/pack_hwpx.py $WORK output.hwpx
```

### Phase 5. 자가 평가 (필수)

빌드 후 다음 체크리스트를 실행한다. 미달 항목 있으면 수정 후 재점검 (최대 2회).

`build_report.py v2`는 빌드 직후 자동 검증을 수행하고 결과를 출력한다. 결함 1건 이상 발견 시 종료 코드 1을 반환하므로, 출력 로그를 확인한다.

| 점검 항목 | 기준 | 자동 검증 |
| --- | --- | --- |
| 금지어 | 0건 | O |
| 추상 형용사·모호 부사 | 0건 | 수동 |
| 한 항목 3줄 초과 | 0건 | 수동 |
| 추진 배경 등급 A 출처 | 1건 이상 | 수동 |
| 자리표시자 `[…]` 잔존 | 0건 | O |
| **지원대상 표 행 수** | **JSON 입력 행 수와 일치** | **O** |
| **평가항목 표 행 수** | **JSON 입력 행 수와 일치** | **O** |
| **문의처 표 행 수** | **JSON 입력 행 수와 일치** | **O** |
| **연락처 중복** | **원본 미중복 → 본문 중복 0건** | **O** |
| 단계-일정 정렬 | 단계명과 일정이 같은 표 행 내 위치 | 수동 |
| 표 헤더 셀 정렬 | 가운데 정렬 | 수동 |
| 표 본문 셀 정렬 | 텍스트 좌측·숫자 가운데 | 수동 |

2회 후에도 미달이면 미달 항목·위치·사유를 사용자에게 보고한다.

자동 검증 출력 예시:

```
[표 행 복제 결과]
  지원대상: 6행
  평가항목: 3행
  문의처: 3행
  진행단계: 5/5단계 치환

[무결성 검증]
  미교체 자리표시자: 0건
  표 행 수 일치:
    [OK] 지원대상: 기대 7행 / 실제 7행
    [OK] 평가항목: 기대 4행 / 실제 4행
    [OK] 문의: 기대 4행 / 실제 4행
  연락처 중복: 0건
  금지어 검출: 0건

[종합] 결함 0건 검출됨
[통과] 모든 무결성 검증 통과
```

### Phase 6. 사용자 검토·수정

1차 산출 후 사용자가 수정을 요청하면 3가지 유형으로 분류해 처리한다.

| 요청 유형 | 처리 방식 |
| --- | --- |
| 부분 교체 (특정 표·문단) | 해당 부분만 다시 빌드 |
| 전체 톤 조정 | Phase 3부터 재작성 |
| 사실 정정 (수치·날짜) | 해당 토큰만 치환 후 재패킹 |

## 7섹션 구조 상세

### 머리말

```
[기관명] 공고 제[YYYY-NN]호

[보고서·공고문 제목 입력]

[안내 문구 2~3줄 이내. 사업 목적·주체·대상 범위를 한 문단으로 압축]

                                          [YYYY]년 [MM]월 [DD]일
                                          [발신 기관·부서명]
```

### 1 추진 배경 (4단 구조)

```
1   추진 배경

□ 추진 필요성
 ◦ [통계청·정부공식 자료의 핵심 수치 1~2문장]
  - [세부 근거: 비교 수치·비율·변화율]
 * 출처: 통계청 [통계명], [발표연도]
 ◦ [현황이 정책·교육·현장에 시사하는 바 2~3줄]

□ 추진 목적
 ◦ [목적 1: 행동형 동사로 직접 성과 기술]
 ◦ [목적 2: 사업의 간접 효과 2줄 이내]
```

### 2 사업 개요

```
2   사업 개요

□ 사업명 : [정식 명칭]
□ 사업기간 : [YYYY.MM.DD ~ YYYY.MM.DD] (총 [N]개월)
□ 사업예산 : [총 ○○억 ○○백만원 / 기관부담 ○○ · 자부담 ○○]
□ 주요 내용
 ◦ [핵심 활동 1: 2~3줄 압축]
 ◦ [핵심 활동 2: 활동 단위·결과 단위로 분리]
```

### 3 지원 대상·규모

4열 비교표: 구분 | 대상 요건 | 지원 내용 | 지원 규모

신청 제외 대상은 `◈` 박스로 별도 표기.

### 4 진행 절차

5열 단계 흐름표: 1단계 → 2단계 → 3단계 → 4단계 → 5단계
(예: 모집·공고 → 접수 → 평가·선정 → 협약·개시 → 정산·결과)

### 5 평가 기준·가점

3열 평가표: 평가 항목 | 배점 | 평가 내용

가점 항목은 `◦`로 나열.

### 6 유의 사항

모든 항목을 `◈`로 시작. 마지막에 "본 공고문에 명시되지 않은 사항은 관계 법령에 따른다" 일반 단서 필수.

### 7 문의처

3열 표: 기관·부서 | 연락처 | 문의 내용

## 계층 기호 사용법

| 계층 | 기호 | 들여쓰기 | 용도 |
| --- | --- | --- | --- |
| 섹션 헤더 | 숫자 + 음영선 | 0 | `1·2·3` 대섹션 (paraPr 27 + charPr 13) |
| 대제목 | `□` | 0 | 섹션 내 주요 항목 (paraPr 24) |
| 중제목 | `◦` | 1단 | 대제목 하위 (paraPr 25) |
| 세부 | `-` | 2단 | 중제목 하위 부연 (paraPr 26) |
| 번호 | `①②③` | 1~2단 | 순서·조건 열거 |
| 강조 | `◈` | 0~1단 | 박스성 유의 사항 |
| 각주 | `*` (9pt) | 2~3단 | 단서·예외·정의 (charPr 11) |

## 빌드 도구

### scripts/pack_hwpx.py

디렉토리 → .hwpx 패키징 (mimetype first, ZIP_STORED). 표준 라이브러리만 사용.

```bash
python3 scripts/pack_hwpx.py <work_dir> <output.hwpx>
```

### scripts/build_report.py (v2)

JSON 형식의 보고서 데이터를 받아 section0.xml의 자리표시자를 치환한다.
v2부터 표 행은 데이터 길이만큼 동적 복제되고, 빌드 직후 무결성 검증이 자동 실행된다.

```bash
python3 scripts/build_report.py --work <unpacked_dir> --data <report_data.json>
```

가변 행 규칙
- `지원대상` 배열 길이만큼 표 행 자동 생성 (1~N행)
- `평가항목` 배열 길이만큼 표 행 자동 생성 (1~N행)
- `문의` 배열 길이만큼 표 행 자동 생성 (1~N행)
- `단계` 배열은 고정 5단계 (5개 미만이면 빈 셀로 남음)
- `제외대상` 배열은 첫 2개만 본문 노출 (3개 이상이면 첫 2개를 묶거나 분리)

### assets/blank_template.hwpx

빈 표준 양식 (한글에서 바로 열림). 7섹션 자리표시자 포함. 두 PDF 공고문(2024년 수출지원기반활용사업·2026년 제조AI 스마트공장 재직자 장기심화과정)에서 추출한 양식 그대로 적용.

### Code Execution 환경 요구사항

- Python 3.9+
- 표준 라이브러리만 사용 (zipfile, shutil, pathlib, xml.etree, json, argparse)
- 추가 패키지 불필요

## Critical Rules

1. **.hwpx 전용**: .hwp(바이너리)는 한글에서 .hwpx로 저장 후 사용
2. **mimetype 위치**: ZIP 첫 엔트리, ZIP_STORED 압축
3. **자리표시자 보존**: 사용자가 정보 미제공한 항목은 `[…]`로 남겨두기 (삭제 금지)
4. **통계 출처 표기 필수**: 추진 배경의 모든 정량 데이터는 `*` 각주로 출처 명시
5. **금지어 0건 보장**: 자가 평가에서 발견 시 무조건 수정
6. **3줄 초과 항목 0건**: 발견 시 분리하거나 표로 전환
7. **표 헤더 배경색**: #DAEEF3 (연한 청록)로 통일
8. **종결어미 일관**: 한 문서 내 ~합니다체 또는 명사형 중 하나로 통일
9. **표 행 무결성**: 지원대상·평가항목·문의처 표는 JSON 입력 행 수와 산출물 행 수가 일치해야 함 (build_report.py v2가 자동 검증)
10. **연락처 중복 금지**: 원본 데이터에 중복이 없는데 산출물에 동일 연락처가 2회 이상 나타나면 결함 (셀 토큰 충돌 의심)
11. **단일 스크립트 원칙**: 보강 스크립트 추가 작성 금지. 자리표시자 미교체 발생 시 build_report.py v2를 수정하여 해결
